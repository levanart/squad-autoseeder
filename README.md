# 5thMR Squad Autoseeder

Windows-клиент для автоматического подключения к игровому серверу Squad, которому в данный момент нужна помощь с заполнением. Приложение получает актуальное состояние серверов от сервиса 5thMR, выбирает назначенную цель и открывает стандартную ссылку подключения Squad.

> Клиент рассчитан на доверенную инфраструктуру 5thMR. После авторизации сервер может отправить клиенту ограниченный набор команд, включая закрытие Squad и выключение компьютера. Подробнее — в разделах «Приватность и данные» и «Чувствительные действия».

## Возможности

- авторизация через Steam в системном браузере;
- безопасное сохранение сессии средствами Windows;
- получение списка серверов, онлайна, очереди и текущей цели;
- запуск и остановка режима автосидинга;
- автоматическое подключение к выбранному серверу через штатную ссылку запуска Steam;
- автоматическое восстановление соединения после кратковременного сбоя сети;
- контролируемые повторные подключения к назначенной цели с cooldown и увеличением задержки;
- работа в области уведомлений после закрытия окна и явная команда выхода;
- запуск автосидинга по расписанию Windows с опцией пробуждения компьютера;
- мониторинг загрузки и температуры CPU/GPU, а также использования памяти;
- таймер закрытия Squad или выключения компьютера;
- приём ограниченных удалённых команд от сервиса 5thMR;
- постоянный ротационный журнал событий без записи токенов сессии.

## Системные требования

- Windows 10 или Windows 11;
- установленный Steam и Squad — для подключения к серверу;
- .NET 10 Desktop Runtime — для framework-dependent сборки;

Для самостоятельной сборки нужен .NET 10 SDK под Windows.

## Установка

### Готовая сборка

Если вам передан официальный архив или исполняемый файл:

1. Распакуйте приложение в отдельную папку, доступную вашему пользователю.
2. Запустите `5thMR.Autoseeder.exe`.
3. Нажмите кнопку входа и завершите авторизацию Steam в браузере.
4. Вернитесь в приложение и запустите автосидер.

Приложение регистрирует пользовательский протокол `autoseeder://`, чтобы браузер мог вернуть результат авторизации в уже запущенный клиент. Регистрация выполняется только для текущего пользователя Windows.

### Сборка из исходников

```powershell
git clone https://github.com/levanart/squad-autoseeder.git
cd squad-autoseeder
dotnet restore .\autoseeder.slnx
dotnet build .\autoseeder.slnx -c Release
```

Результат обычной сборки находится в `bin\Release\net10.0-windows\`.

Для автономной публикации под 64-битную Windows:

```powershell
dotnet publish .\Autoseeder.Client.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true
```

Результат публикации появится в `bin\Release\net10.0-windows\win-x64\publish\`. Каталоги сборки намеренно исключены из Git.

Для воспроизводимой подготовки self-contained single-file архива, SHA-256 списка и JSON-манифеста используйте локальный скрипт:

```powershell
.\scripts\New-Release.ps1 -Version 0.1.0
```

Файлы создаются в `artifacts\`. Скрипт сортирует содержимое архива и задаёт одинаковые временные метки ZIP-записей. Публикация релиза и доверенная доставка артефакта выполняются отдельно; автоматическое обновление в клиент не встроено.

## Версии и релизы

Версия приложения задаётся свойствами MSBuild `Version`, `AssemblyVersion`, `FileVersion` и `InformationalVersion`. Локальные значения по умолчанию находятся в `Autoseeder.Client.csproj`; release workflow переопределяет их значением тега.

Push тега строгого вида `vMAJOR.MINOR.PATCH` запускает `.github/workflows/release.yml`. Для тега `v1.4.0` в `origin` должна существовать ветка `release/v1.4.0`, причём тег обязан указывать точно на её вершину. Workflow публикует self-contained single-file сборку `win-x64`, готовит детерминированный ZIP, `SHA256SUMS.txt`, `release-manifest.json` и создаёт черновик GitHub Release.

Для Authenticode-подписи добавьте одновременно два GitHub Actions repository secret:

- `CODE_SIGNING_PFX_BASE64` — PFX/P12 целиком в Base64;
- `CODE_SIGNING_PFX_PASSWORD` — пароль PFX/P12.

Другие secrets не нужны: `GITHUB_TOKEN` предоставляется GitHub автоматически. Один заполненный signing secret без второго считается ошибкой. Если оба signing secret отсутствуют, релиз собирается без подписи и помечается как `unsigned` в notes и манифесте. Если secrets настроены, любая ошибка подписи или её проверки останавливает релиз.

Полный порядок работы с `main`, `dev` и ветками конкретных релизов описан в [`docs/RELEASES.md`](docs/RELEASES.md). Пустая wildcard-ветка `release/v*.*.*` не создаётся: вместо неё перед каждым релизом создаётся `release/vX.Y.Z`.

## Как пользоваться

1. Запустите приложение. Одновременно работает только один экземпляр клиента.
2. Войдите через Steam. Логин и пароль вводятся только на стороне Steam в системном браузере.
3. Нажмите «Запустить». Клиент подключится к сервису и получит состояние серверов.
4. Когда сервис назначит сервер для сидинга, приложение откроет его ссылку подключения через Steam.
5. Нажмите «Остановить», если больше не хотите автоматически переходить на назначенный сервер.

При необходимости можно запланировать закрытие Squad или выключение компьютера на конкретное время либо через указанное количество минут. Активный таймер сохраняется между запусками клиента.

В блоке «Автозапуск» можно создать задачу Планировщика заданий Windows. В назначенное время клиент запускается с аргументом `--scheduled-start`, автоматически подключается к сервису и включает автосидинг. Для такого запуска заранее выполните вход через Steam. Опция пробуждения использует `WakeToRun`; её фактическая работа зависит от поддержки таймеров пробуждения компьютером и настройками Windows.

Кнопка закрытия скрывает окно в область уведомлений. Двойной щелчок по значку возвращает окно, а полное завершение выполняется пунктом «Выйти» в меню значка.

## Приватность и данные

### Что хранится на компьютере

Данные клиента находятся в `%LOCALAPPDATA%\5thMR\Autoseeder\`:

- `session.dat` — токены авторизованной сессии. Файл зашифрован Windows DPAPI и привязан к текущей учётной записи Windows;
- `client-settings.json` — случайный идентификатор установки, активный таймер и выбранное действие таймера.
- `logs\autoseeder-*.log` — до 10 ротационных файлов журнала размером не более 2 МБ каждый.

Кроме того, в профиле текущего пользователя Windows создаётся регистрация протокола `autoseeder://`. Пароль Steam приложение не получает и не сохраняет.

### Что отправляется сервису

После входа клиент поддерживает соединение с сервисом 5thMR. Примерно раз в две секунды он может отправлять:

- случайный идентификатор установки и имя компьютера;
- версию клиента;
- состояние автосидинга и признак запущенного Squad;
- время и тип запланированного действия, если таймер установлен;
- загрузку и температуру CPU;
- использование оперативной памяти;
- название, загрузку и температуру GPU.

Также клиент отправляет подтверждение выполнения или ошибку для полученных удалённых команд. Эти данные нужны для отображения состояния клиента, управления сидингом и диагностики доступности устройства.

### Журнал

Журнал в интерфейсе содержит последние 200 сообщений, а полная диагностическая история записывается в ротационные файлы. Перед записью клиент маскирует JWT, Bearer-значения и параметры с именами токенов/секретов. Не прикладывайте `session.dat` к отчётам об ошибках.

## Чувствительные действия

Сервис может отправить только заранее предусмотренные команды:

- запустить или остановить автосидинг;
- закрыть процессы Squad;
- установить или отменить таймер закрытия Squad;
- установить или отменить таймер выключения компьютера;
- немедленно выключить компьютер.

Для закрытия Squad приложение сначала пытается закрыть главное окно игры, а затем, если процесс не завершился, принудительно завершает дерево процессов. Выключение выполняется штатной системной командой Windows. Клиент сообщает сервису результат выполнения команды.

Используйте приложение только с учётной записью и сервисом 5thMR, которым вы доверяете. Перед важной работой учитывайте, что команда выключения может завершить сеанс Windows без дополнительного подтверждения в интерфейсе.

## Что приложение не делает

- не запрашивает и не хранит пароль Steam;
- не читает файлы, документы, историю браузера, сообщения или буфер обмена;
- не записывает экран, звук и нажатия клавиш;
- не предоставляет серверу произвольный запуск команд или скриптов;
- не устанавливает системную службу; задачу автозапуска создаёт только по явной команде пользователя в интерфейсе;
- не обновляет себя автоматически;
- не публикует локальные токены, настройки или телеметрию в этот репозиторий;
- не гарантирует свободное место на сервере и не обходит очередь Squad.

## Интеграция с API

Авторизация начинается в системном браузере. После успешного входа сервис возвращает приложение через пользовательский URI, а клиент сохраняет выданную сессию локально. Перед истечением короткоживущего токена клиент обновляет сессию по защищённому HTTP-соединению.

Рабочее состояние передаётся через SignalR поверх WebSocket. Клиент:

1. подключается с токеном текущей сессии;
2. запрашивает состояние автосидера и список серверов; для каждого сервера получает только признак присутствия текущего пользователя, без списка игроков или Steam ID;
3. получает обновления состояния и ограниченные команды;
4. отправляет телеметрию и подтверждения команд;
5. автоматически переподключается после временного разрыва связи.

Адрес сервиса и контракт сообщений задаются в исходном коде клиента и должны соответствовать развёрнутой версии API. Репозиторий не содержит серверных ключей, учётных данных или конфигурации внутренней инфраструктуры.

## Внутренняя архитектура

```text
App.xaml / App.xaml.cs
├── запуск одного экземпляра
├── регистрация autoseeder://
└── создание главного окна

MainWindow.xaml / MainWindow.xaml.cs
├── интерфейс и журнал
├── состояние серверов и автосидинга
├── системные метрики
└── таймер и обработка разрешённых команд

Services/
├── AuthService                 авторизация и обновление сессии
├── TokenStore                  защищённое локальное хранение токенов
├── AutoseederHubClient         SignalR-соединение и протокол клиента
├── HardwareMonitorService      чтение датчиков системы
├── ClientRuntimeService        состояние Squad и запланированные действия
├── ScheduledStartService       задача Windows Task Scheduler и WakeToRun
├── TrayIconService             значок и явный выход из области уведомлений
├── ReconnectStateMachine       cooldown/backoff подключения к цели
├── AppLog                      ротационный файловый журнал и маскирование секретов
├── ProtocolRegistration        регистрация пользовательского URI
└── SingleInstanceService       один процесс и передача URI между запусками

Models/                         модели API, телеметрии и интерфейса
Controls/                       пользовательские WPF-контролы
Assets/                         иконка и фон приложения
```

Проект намеренно остаётся небольшим: интерфейс, локальные службы и сетевой клиент собраны в одном WPF-приложении без фоновой Windows-службы.

## Удаление

1. Удалите задачу в блоке «Автозапуск», затем выберите «Выйти» в меню значка приложения.
2. Удалите папку, в которую оно было распаковано или опубликовано.
3. Удалите `%LOCALAPPDATA%\5thMR\Autoseeder\`, чтобы стереть сохранённую сессию, идентификатор установки, таймер и журналы.
4. При необходимости удалите пользовательскую регистрацию протокола `autoseeder://` из `HKEY_CURRENT_USER\Software\Classes\autoseeder`.

Перед удалением приложения отмените активный таймер. Простое удаление файлов приложения не удаляет локальные данные и регистрацию протокола автоматически.

## Разработка

Минимальная проверка перед изменениями:

```powershell
dotnet restore .\autoseeder.slnx
dotnet build .\autoseeder.slnx -c Release --no-restore
```

Не добавляйте в коммиты `bin/`, `obj/`, пакеты публикации, `.env`, токены, дампы, профили публикации и пользовательские файлы IDE. Перед отправкой изменений просмотрите `git status` и проверьте staged-содержимое на секреты.
